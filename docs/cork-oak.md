# Cork oak production resource

Cork oak is an evergreen tree with a leaning trunk, low forks and a broad, irregular crown. Its default height is 9–11 blocks with a canopy up to 14 blocks across; variation in branch height and direction avoids the silhouette of a tall, narrow conifer. This is deliberately larger and wider than a standard small Minecraft oak while remaining practical to harvest from the ground or a short platform.

The Royal Horticultural Society describes *Quercus suber* as a spreading, branched evergreen exceeding 12 metres high and 8 metres wide, with deeply fissured bark and a brick-red surface exposed by cork removal. The [RHS plant profile](https://www.rhs.org.uk/plants/14309/quercus-suber/details), its [photograph of an open-grown cork oak](https://apps.rhs.org.uk/plantselectorimages/detail/JFQuercussuber5.JPG), and [International Dendrology Society photographs](https://www.treesandshrubsonline.org/articles/quercus/quercus-suber/) informed the low fork, crooked trunk, rounded evergreen crown and exposed-bark colours. Dimensions are a Minecraft adaptation, not a literal metre-for-block recreation.

Cork oaks appear as occasional small groves in newly generated forest, plains, sunflower plains, savanna and savanna plateau chunks. These are Minecraft analogues for the open woodland and warm Mediterranean habitat described by RHS, rather than a claim that all those real-world ecosystems contain cork oak. The biome tag `vinum:has_cork_oak` is data-pack extensible. A grove candidate is attempted once per 64 eligible chunks, with one main tree and up to two neighbours, bounded to six neighbour attempts. Terrain, loaded generation area and obstructions may reduce the actual number. Existing blocks and structures are not overwritten. Plant dropped saplings on ordinary tree-compatible soil; normal growth and bone meal both use the same configured feature.

Use an axe on a log to peel 2–3 cork bark while leaving the trunk standing. Bark changes to a reddish used texture and cannot be harvested again until it regenerates. One bark crafts four wine corks. Survival harvesting uses one axe durability; creative harvesting produces no item drops. Leaves have normal sapling/Fortune drops and can be collected with shears or Silk Touch.

[Amorim's production description](https://www.amorimcork.com/en/cork-and-wine/raw-material-and-production-process/) describes careful hand stripping without felling and a minimum nine-year harvest interval. The default game interval compresses that cycle into nine Minecraft days (216,000 server ticks, three hours at 20 TPS). Configure `corkRegrowthTicks` in the world's `serverconfig/vinum-cork-oak-server.toml`. The clock is server game time, not sun/time-of-day, and does not run while the server is stopped. Existing harvest deadlines retain the interval that applied when harvested.

The deadline survives chunk unload, save/reload and picking up/replacing the log. Used logs carry their own block-entity data and do not stack; fresh logs stack normally. Regrowth also requires connected cork logs to reach soil and cork leaves, so detached lumber does not regenerate. The bounded search checks at most 256 logs and never loads chunks. Unloaded connections defer regrowth until available. An expired but nonliving log checks again after 1200 ticks, avoiding constant polling; axe interaction checks immediately. Living structure detection is intentionally a simple gameplay rule, not a simulation of cambium or root tissue.

All five new tree textures are 16×16; source prompts are in `cork-oak-art-prompts.json`. Existing wine-cork and cork-bark artwork is reused unchanged by this feature. Dedicated server GameTests cover harvest duplication, durability, persisted item deadlines, regrowth boundaries, living-tree requirements, blocked placement and sapling-grown branching/crown bounds. Client appearance remains for in-game visual review.
